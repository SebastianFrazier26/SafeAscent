SafeAscent

Route-level risk forecasts for climbers. For a route and a day in the next few days, SafeAscent scores risk from 0 to 100 using past accidents nearby, weighted by how relevant each one is, and how closely the coming weather matches the weather before each of them.

Revival in progress. safeascent.us is offline while the data pipeline, model, and operations are rebuilt, and the app is being relaunched. The code is public and changing week to week. No score shown before the rebuild should be relied on.

What it does

One number, one scale

Each route gets a 0–100 risk score for today and the next two days, precomputed nightly. The same four bands are used everywhere, each including its lower edge:

Low0 – 25
Moderate25 – 50
Elevated50 – 75
High75 – 100

Never a made-up number

A score that is missing or failed to load reads Unavailable in gray. It never falls back to 0.

When no past accident contributes to a route, it reads Too little evidence to estimate risk yet. No local accidents is not the same as safe.

How the score works

Every historical accident adds some influence to a route's score. How much depends on how far away it was, how long ago, what kind of climbing it was, how severe, how close in elevation and grade, and above all on whether the weather before it looks like the weather coming up.

influence = spatial × temporal × route_type × severity × elevation × grade × weather³
score     = min(100, 7 × Σ influence)
  • Weather similarity compares a 7-day weather window for the climb with the 7 days before each accident: temperature, precipitation, wind, visibility, cloud cover and freeze-thaw cycles, each matched with a weighted correlation that favors the days closest to the climb. Weather more than 2 standard deviations from that location's recent history amplifies it. It is cubed, so weather dominates, and an accident whose weather matches less than 25% is dropped.
  • Distance fades on a Gaussian curve whose width depends on the planned route type: about 25 km for sport, 75 km for alpine. There is no hard cutoff, so a distant accident in near-identical weather can still count.
  • Time fades slowly, over years. Terrain and objective hazards change little, so recency is deliberately a modest factor, with a small boost for accidents in the same season.
  • Route type uses an asymmetric matrix. Sport-climbing accidents in bad weather are a strong signal for alpine routes (the canary effect), but alpine-specific accidents say less about sport routes.
  • Severity is a mild boost: fatal 1.3×, serious 1.1×, minor 1.0×.

Planned next: a model that also borrows evidence from routes with similar characteristics anywhere, not only from accidents nearby, so that a route with no local history is not read as safe.

Architecture

Hosted on Railway (frontend, API, worker, beat, Redis) with Postgres on Neon. The API reads with a role that can write only the score history table; data jobs run with their own separately scoped role. Missed nightly runs page through healthchecks.io dead-man checks.

Data and rules

  • Accidents: American Alpine Club, Avalanche.org/CAIC and NPS records, cleaned and de-duplicated by audited repair jobs. Not redistributed.
  • Weather: Open-Meteo forecasts and ERA5 reanalysis history keyed to each crag's local calendar day. The live app never calls a weather API at request time for history.
  • Licensing: code is Apache-2.0; data follows DATA_LICENSE.md. CI guards block scraper code anywhere in the repository and third-party route identifiers in its data, docs and test fixtures.
