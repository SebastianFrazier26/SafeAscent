# SafeAscent: agent guide

Climbing-route risk forecasts from historical accident data and weather. FastAPI + Celery backend on Railway, PostGIS on Neon, React frontend. Read `README.md` for the point of the project and `DATA_LICENSE.md` before touching data.

## Commands

Backend (run from `backend/`):
- `uv sync`: install (lockfile committed; CI runs `uv sync --frozen`). `default-groups = ["dev", "pipelines"]` in `pyproject.toml`, so a plain `uv sync` already installs the `pipelines` group (`timezonefinder`, `tzdata`, `h3`, `rasterio`) the local-day/ERA5 and static-features jobs and their tests need. `uv sync`'s groups are exact — `uv sync --group dev` alone drops `pipelines` rather than adding to the default set, so name both groups if you narrow the sync. The API image builds with `--no-group pipelines` (not needed at serve time).
- `uv run pytest`: tests. `needs_data` tests (populated DB/live services) are deselected by default (`-m 'not needs_data'`); run them explicitly with `-m needs_data`. Tests that need a throwaway Postgres (`tests/test_migrations.py`, `test_roles_phase2.py`, `test_migration_0004.py`, `test_ingest_log.py`, `test_mp_ticks_quarantine.py`, `test_mp_tick_aggregates.py`, and others built on `tests/pgtest.py`) need `MIGRATIONS_TEST_ADMIN_URL` (a superuser URL to a maintenance DB) and skip without it; the role-script tests (`test_migrations.py`, `test_roles_phase2.py`) also need `psql` 15+ on `PATH` (under `CI=1` a missing `psql` fails instead of skipping). `VERIFY_DATABASE_URL=<analyst url> uv run pytest -m db tests/verify`: read-only acceptance checks against a live branch or prod; `db`-marked tests are excluded from the default `uv run pytest` (`addopts` deselects `not needs_data and not db`) and skip individually without `VERIFY_DATABASE_URL`.
- `uv run ruff check . ../scripts/`: lint (rules `E4,E7,E9,F`, pinned ruff 0.8.4). Covers all of `backend/` (ruff's default excludes skip `.venv`, `__pycache__`, etc.) plus the top-level `scripts/`.
- `uv run mypy`: types. Scope comes from `pyproject.toml` (`files = ["app"]`); most of `app/` is an ignore-errors allowlist until typed, strict on `app.config`, `app.services.risk_bands`, `app.healthchecks`, and all of `app.pipelines` (`app.pipelines`, `.validate`, `.grid`, `.ingest_log`, `.db`, `.mp_ticks_quarantine`, `.mp_tick_aggregates`, `.route_types`, `.area_tree`, `.mp_catalog`, `.textsim`, `.geo`, `.gnis`, `.open_meteo`, `.cell_conditions`, `.localday`, `.pro_window`, `.era5_fill`, `.normals`, `.era5_window`, `.r6_verify`, `.accident_facts`, `.dem`, `.epqs`, `.static_features`, `.exposure_math`, `.exposure_components`, `.exposure`), `app.data.repair.*` (`framework`, `sources`, `review`, `dates`, `checks`, `severity`, `geocode`, `activity`, `dedupe`, `experience`, `area_weekly`, `legacy_links`, `r10_llm`, `__main__`), and, minus the subclassing-Any check SQLAlchemy's `declarative_base()` always trips, `app.models.pipeline`, `app.models.reference`, `app.models.conditions`, `app.models.catalog`, `app.models.features`, `app.models.links` and `app.models.exposure`, with a celery-adjacent variant (same flags minus the subclassing-Any/untyped-decorator checks celery's own missing types always trip) on `app.celery_signals` and `app.tasks.ops` — extend either list as modules graduate.
- `uv run python -m app.pipelines.<job>`: Phase 2 data jobs (`mp_ticks_quarantine`, `mp_tick_aggregates --sqlite <export> [--scope ice_mixed|rock] [--dry-run]`, `mp_catalog refresh [--dry-run]` (rebuilds `canonical_areas`/`canonical_routes`; run after every MP scrape load), `gnis --file <DomesticNames zip>`, `localday register`, `era5_window register|plan|run --window-start YYYY-MM-DD [--initial-window] --max-units N` — the only ERA5 entry point; refuses outside a Professional window — `r6_verify`, `accident_facts --file <facts CSV> [--dry-run] [--apply-route-ids] [--overwrite]` (R11; see `data/manual/README.md`), `static_features points|elevation [--limit N]|routes|epqs-check` (3DEP elevation and the per-route feature table on the MP catalog; `points` registers only areas holding a scorable route and reports `scorable_routes_no_tz` (scorable routes whose point has no timezone); `points` before `routes` — `routes` refuses outright if any scorable route's point is missing from `feature_points`; `elevation` samples up to `--limit` points, default 5000, oldest-attempted first, and leaves a point pending on a transient DEM error; `epqs-check` cross-checks a stratified sample against USGS EPQS and fails closed, logging `status = 'rejected'`, if the gate doesn't pass — see `app/pipelines/epqs.py`; run it before every `routes` rebuild)); connect as `ingest` via `INGEST_DATABASE_URL` and refuse without it; `app.pipelines.db.ingest_engine` also refuses Neon's `-pooler.` host (matched case-insensitively) for every ingest job. Calls to USGS (EPQS, 3DEP tiles, GDAL reads) send `app.pipelines.USER_AGENT`, `SafeAscent/<pyproject version> (+repo URL)`.
- `--scope rock` loads the private rock export: aggregate tables only, never a path inside the repo, routes the seam already holds at that scrape time skipped (reloading a cumulative export is a no-op); run from the Mac as `ingest` (exposure plan Task 3). Every load, either scope, is preceded by the private `~/Developer/safeascent-private/export_tick_aggregates.py --scope rock|ice_mixed`, which snapshots the scraper SQLite (read-only, backup API) into a new aggregate-only file under `~/Developer/safeascent-private/exports/`; the loader refuses the scraper's own database. That script never enters this repo.
- `uv run python -m app.pipelines.exposure build [--cutoff YYYY-MM-DD] [--dry-run] | drop --as-of D --cutoff D`: exposure snapshots in `internal.exposure_index`, as `ingest` (never served). One REPEATABLE READ snapshot per build; the newest 3 production snapshots (`data_cutoff = as_of`) are kept, backtest snapshots stay until dropped; `drop` exits non-zero if no snapshot matches. Build after the January ERA5 window (the CLI warns about the January blackout). `EXPOSURE_ENABLE_MP_TICKS=false` is the removal drill: `( export EXPOSURE_ENABLE_MP_TICKS=false; uv run python -m app.pipelines.exposure build --dry-run )` changes only the `mp_ticks` digest. Tick coverage is biased (accident areas were scraped first): consumers must use `tick_coverage`, never read a partial sum as low traffic. Details in `data/DATABASE_STRUCTURE.md`.
- `uv run python -m app.pipelines.catalog_cycle run [--skip-epqs] [--max-rounds N]`: the whole catalog and features cycle as `ingest` (refresh, points, elevation rounds, EPQS gate, then routes only after the gate passes; a failed gate blocks routes); exit 0 ok, 1 rejected/failed, 2 incomplete (re-run once 3DEP recovers). When the only points left are pending a transient retry, the gate runs over the sampled points and, if it passes, routes are rebuilt with NULL elevation for the pending ones, and the run still reports incomplete and pings `/fail`. `--skip-epqs` skips the gate and so rebuilds routes ungated (on-demand only; the cron never passes it). Refuses Neon's `-pooler` host. Prod runs it as the `catalog-cycle` cron service.
- `uv run python -m app.data.repair <step> [--apply]`: Phase 2a accident repairs as `ingest` (dry run by default; `--apply` writes, audited per field in `internal.accident_revisions`). Rule steps: `r2r1`, `r9`, `r3` (R3a/R3 geocodes; needs GNIS loaded), `r4` (activity classes; needs `r3`), `r5` (duplicates; needs `r3` and `r4`; `--apply --out` also writes the owner review CSV), `r12` (experience facts), `r10` (accident route links on the MP catalog: links legacy routes whose MP id is in the catalog, lists the rest in `internal.r10_unresolved` with ranked candidates, including reason `not_in_catalog` for an accident whose own `mp_route_id` the catalog does not hold yet; never links by name, never writes `accidents`), `r7` (one-time `area_weekly_weather.longitude` sign fix; refuses unless exactly one row is positive and equals 113.2). Read-only checks: `r3-states` (raw state values: unmapped and foreign ones need the owner before `r3 --apply`), `r3-clusters`. Owner round trips, each `*-export --out` once (refuses to replace a file unless `--overwrite`) then `*-import --review-file` (`--apply` where it writes rows): `r1`, `r9`, `r3a`, `r3-plot`, `r3-ambiguous`, `r4-review`, `r5-import`, `r10` (`r10-export --out`, `r10-import --review-file [--apply]`; owner decisions persist across `r10` reruns and a database trigger refuses any change to a decided row; every row in the import file must carry `link` or `no_link`, so delete the rows you did not decide before importing; `candidates_searched = False` means no coordinate search ran, not that it found nothing; a candidate's `km` is approximate when its `coord_precision` is `inherited`); golden draws `r4-golden-export`, `r12-golden-export`. Runbooks call it through `backend/scripts/runbook_helpers.sh`, which refuses unless `TARGET_HOST` is set (a Neon branch host, or `production`). It also holds the prod-gate helpers (`same_ids`, `gate_pass`/`gate_require`) and `bg_start`/`bg_wait` for applies longer than an agent's 10-minute tool call; a runbook block never defines a helper for a later block.
- `uv run --group llm python -m app.data.repair.r10_llm plan|probe|sample|sample-csv|gate|run|apply` (runbooks: `INGLLM`): the R10 LLM pass over the residue, as `ingest`. `plan`, `sample-csv --run-id ID --out CSV`, `gate --review-file` and `apply [--apply]` never call the API; `probe --model haiku|sonnet --max-usd X` (models.retrieve plus one synthetic fixture call, the runbook's verify gate), `sample --model … --n N --max-usd X --out CSV [--seed S]` and `run --model … --max-usd X` are paid and need `ANTHROPIC_API_KEY` exported in the shell, never in a file (they refuse if any `backend/.env*` file holds it). `--max-usd` is cumulative per model and prompt version across every paid run (ledger in `source_ingest_log`, source `r10_llm`; capped at the owner's $12 Haiku / $22 Sonnet), must be finite and above 0, one paid run at a time (advisory lock, re-checked before every call), at most 2 attempts per accident, no SDK retries, and a reply from any model but the pinned id stops the run. `run` and `apply` refuse unless the latest gate for the same model and prompt version passed, so the order is sample, owner spot-check, `gate`, `run`, `apply`; `gate` saves the spot-check answers as R10 owner decisions whether or not the gate passes (an earlier owner decision stands), and `apply` never overrides them. Paid work runs on prod only (the ledger and gate live in the target database; Task 16 of `docs/superpowers/plans/2026-10-12-mp-catalog-similarity.md`). The `llm` group (pinned `anthropic`) is in no image and no default sync.
- `uv run --group train python -m app.ml.train ...`: Phase 3 training, as `trainer`, from the owner's Mac only (`TRAINER_DATABASE_URL` in gitignored `backend/.env.trainer`; no GitHub secret). Subcommands are filled in by Task 20.
- `uv run alembic upgrade head`: migrations. Needs `MIGRATOR_DATABASE_URL` (the `migrator` role). Never runs on app startup; prod is `alembic stamp 0001_baseline` once, then upgrades from there.
- `uv run uvicorn app.main:app --reload`: API
- `uv run celery -A app.celery_app worker --loglevel=info --concurrency=2 -E` and `uv run celery -A app.celery_app beat --loglevel=info --schedule=/tmp/celerybeat-schedule`: background jobs (beat is a separate process/service from the worker, never combined)

Frontend (run from `frontend/`): `npm ci`, `npm run dev`, `npm test` (watch), `npm run test:run`, `npm run lint`, `npm run typecheck`, `npm run build` (CI also sets `VITE_API_BASE_URL`/`VITE_MAPBOX_TOKEN` build args). `frontend/docker-tests/test_images.sh all` builds and HTTP-checks both `MAINTENANCE_MODE` image variants.

Local stack: `docker compose up --build` (db, redis, api, worker, beat, frontend — same images and start commands as Railway). `scripts/check_compose_matches_railway.py` (CI `guards` job) fails if they drift.

## Service topology

- Railway services: `api` (`backend/railway.toml`), `worker` (`backend/railway-worker.toml`), `beat` (`backend/railway-beat.toml`, exactly one replica — a second double-schedules every task), and `frontend`. One Redis. Postgres/PostGIS on Neon.
- `catalog-cycle` (`backend/railway-catalog-cycle.toml`, `backend/Dockerfile.jobs`): Railway cron, yearly `0 9 2 1 *` UTC plus on demand, auto-deploy off. It is the **only** service holding the `ingest` credential (`INGEST_DATABASE_URL`, direct Neon host, verify-full TLS); never add that credential to another service. Its `DATABASE_URL` is the inert `postgresql+asyncpg://unused@invalid.invalid/unused`. It has no compose counterpart (exempt in `scripts/check_compose_matches_railway.py`'s `NO_COMPOSE_COUNTERPART`); every `backend/railway-*.toml` must be compared or exempted there.
- Deploys: Railway auto-deploys `main` after the `ci-ok` check is green ("Wait for CI"); auto-deploy is off until the Phase 1 relaunch. Migrate before deploy: code whose models map columns a pending migration adds (e.g. `0004`) must not deploy until that migration is on prod (`DEPLOYMENT.md`).
- Alerting: healthchecks.io dead-man checks for the nightly job (`HEALTHCHECKS_NIGHTLY_URL`) and the beat heartbeat (`HEALTHCHECKS_BEAT_URL`). An unset ping URL skips the outbound call with a WARNING (local/CI never call out). `GET /health/worker` returns 503 when the worker heartbeat (`WORKER_HEARTBEAT_TTL_SECONDS`, default 120s) is missing from Redis, and reports the trailing 7-day expired-task counts.

## Data rules

- **No scraper code is ever committed to this repo.** CI's `guards` job runs `scripts/check_no_scrapers.py` on every tracked file (names, banned-host mentions, HTML-parsing/browser-automation imports, and lockfile entries). Clients for open APIs (OpenBeta GraphQL, Open-Meteo, NOAA, USGS, Macrostrat, NWS, AirNow, SNOTEL) are fine and live in the repo.
- Mountain Project: ice/mixed route facts (name, grade, location, type), rock routes, and tick aggregates (ascent counts by season/month) may be displayed; none is bulk-redistributed. No MP prose or descriptions, ever, anywhere — not fixtures, docs, or commits. (Owner decision 2026-09-28; `DATA_LICENSE.md` wording is pending the owner's legal review.)
- The R10 LLM pass sends the DP14 field set to the Anthropic API: short accident fields, the full accident narrative (owner decision 2026-10-12: open-source accident text) and candidate MP facts (names, grades, types, area names); never coordinates, exact dates, URLs or ids. The narrative is never stored in the audit table, logged, or written to a review CSV.
- MP is the primary route source (owner decision 2026-10-12); OpenBeta is not used. See `DATA_LICENSE.md` for the full source-by-source breakdown and verification dates.
- `scripts/check_no_mp_data.py` (CI `guards`) fails on MP route/area URLs or real MP ids (below the synthetic floor 900000000) in tracked files under `data/`, `docs/`, `backend/tests/fixtures/`; test ids start at 900000000. Catalog tables hold derived columns only; names and grades are read from `mp_routes`/`mp_locations`. Route types are `route_types.TYPE_RULE_VERSION` (`rt-mp-v3`: a toprope/aid-only route is `rock`, and a V grade means a boulder); a route's point is always its location's, never `mp_routes` lat/lon (owner decision 2026-10-12). `mp_catalog refresh` upserts and never deletes, and rejects a run whose scorable count drops more than 3% (`MAX_SCORABLE_DROP`). Route and area `type_group` values (`canonical_routes`, `route_static_features`) are `sport`, `trad`, `alpine`, `ice`, `mixed`, `rock` (sport-or-trad, discipline unknown) or `unknown`.
- `static_features` 3DEP sampling (`app/pipelines/dem.py`) stores NULL, never 0, for a masked cell, a declared fill value, or no tile at either resolution (`3dep_13` 1/3″ then `3dep_2` 2″, the fallback decided per point); `nodata`/`no_tile` are terminal `dem_source` values a later run never resamples, while a transient read failure (stalled S3, mid-read error) leaves `dem_source` NULL so the point retries, oldest-attempted first. The EPQS cross-check (`app/pipelines/epqs.py`) samples per slope class up to `MIN_COMPARED` (180 overall)/`MIN_PER_CLASS` (30/class), and fails closed — `source_ingest_log.status = 'rejected'` — if a class's median/p90 |Δ| exceeds its tolerance (by the point's `dem_source`: `3dep_13` `flat` 2 m/5 m, `moderate` 4 m/10 m, `steep` 8 m/20 m, gross 100 m; `3dep_2` `flat` 5 m/12.5 m, `moderate` 10 m/25 m, `steep` 20 m/50 m, gross 200 m; only sampled points are drawn) or its own EPQS-failure share exceeds `MAX_FAILURE_SHARE` (20%). `static_features run_step` never holds a DB transaction across the 3DEP/EPQS network calls: it reads in one short transaction, samples with none open, then writes and logs in a second.
- Weather days are the crag's local calendar day: conditions are keyed by `(grid_bucket, tz, date)`; join accidents through `accidents.tz`. `record_kind = 'stopgap'` rows are Forecast-API past days, not ERA5. Precedence is `era5 > stopgap > forecast` (the upsert's WHERE); a re-fetch that comes back NULL never erases a stored value at equal rank, but an `era5` row still replaces a lower-kind row whole.
- Incident ERA5 history starts `localday.INCIDENT_START` (1990-01-01, owner decision DP1); each incident series' fill reaches back to 1989-12-26 (6 days before, for the first 7-day window). An incident dated before 1990 gets no incident series at all and reads `conditions_missing`, never a zero.
- `era5_window`'s trailing re-fetch of each series' last 90 days (ERA5T → final ERA5 replacement) happens once per Professional window, not once per run inside it.
- `accident_conditions` and localday share the 1990 floor: `0007`'s `INCIDENT_START_SQL` must equal `localday.INCIDENT_START` (`test_localday` pins it).
- `era5_fill` never stores or covers unpublished lag-edge ERA5 days: on an edge chunk (forward, ending within 14 days of the lag edge) a series' `last_era5_date` is its last day with tmax, tmin and precipitation all present that also passed validation, and the rest is asked for again next run. A short all-unpublished edge chunk is `pending_lag_edge` (ok, 0 rows, breaker untouched), a short-of-end one `edge_trimmed`; non-edge chunks ending in unobserved days are rejected, and a forward chunk never extends a span it does not continue.
- Normals use a bucket's alphabetically first timezone (`min(tz)`), one series per bucket.
- `era5_window run` reads `OPEN_METEO_API_KEY` only from the exported process environment, never from `backend/.env` via settings (fail closed); `--incident-start` must be 1989-12-26.
- A Professional month is capped at 5,000,000 Open-Meteo units (`pro_window.WINDOW_UNITS`); the plan gate refuses to buy anything once cumulative spend would pass 4,500,000 (`PLAN_STOP_UNITS`). A fill run's failure breaker stops the window after 3 consecutive failed or rejected chunks/batches, so an outage cannot run the budget down unattended.
- The live app reads historical weather only from `cell_daily_conditions` in our own database — it never calls Open-Meteo at request time. The legacy `weather` table stays only as read-only input to `r6_verify`'s one-time agreement check; it is otherwise unused (`data/DATABASE_STRUCTURE.md`).

## Safety-accuracy rules (owner priority: accurate results over everything else)

- Never display a fabricated risk score. No `|| 0` / `?? 0` (or equivalent) on a risk value in either stack — a missing, malformed, or failed score renders as "Unavailable"/em-dash in neutral gray, never a number. Backend: `tests/test_no_fabricated_risk.py`. Frontend: `riskUtils.test.ts`.
- One risk-band definition: `backend/app/services/risk_bands.py`'s `RISK_BAND_THRESHOLDS` (25/50/75, lower-inclusive) mirrored by `frontend/src/utils/riskUtils.ts`. `backend/tests/test_risk_bands.py` fails if they drift — change both together.
- Insufficient-data rule: no contributing evidence, or a raw score below `MIN_ESTIMABLE_SCORE` (0.05), renders "Too little evidence to estimate risk yet" in gray (`insufficient_data`/`INSUFFICIENT_DATA_COLOR`) rather than a score. Interim until the Phase 3 model borrows evidence from characteristically similar routes anywhere.
